# Roadmap: миграция на Cloudflare Pages + Supabase

Дата: 3 ноября 2026 года. Статус: миграция начата, рабочее переключение не выполнено.

Подготовлен код M0–M5 и инструменты локальной репетиции M7. Проверенный снимок:
542 записи, 1084 карточки, 362 ответа. Восстановление снимка в PostgreSQL/PGlite
сверено с SQLite. Облачные проекты не созданы; hosted Auth/JWT, SMTP, конкуренция
нескольких соединений и мобильный пилот ещё не приняты. M6 остаётся обязательным.
Отчёт и команды: [docs/CLOUD-MIGRATION.md](docs/CLOUD-MIGRATION.md).
Контракт и полная карта API: [docs/CLOUD-CONTRACT.md](docs/CLOUD-CONTRACT.md).
Отметка `[x]` ниже означает выполненный локальный пункт, а не приёмку всего этапа.

Этот документ задаёт новое направление: публичное приложение работает без домашнего
ПК. Он заменяет дальнейшие этапы подключения аккаунтов к домашнему серверу из
[ROADMAP-HYBRID.md](ROADMAP-HYBRID.md). Уже реализованные гостевые экраны и публичная
подборка сохраняют ценность. Старые отчёты о проверках описывают прежнюю архитектуру.

## 1. Результат

- Пользователь открывает постоянный HTTPS-адрес, входит и видит свой прогресс на телефоне и ПК.
- Ввод адреса сервера, Cloudflare Quick Tunnel и включённый домашний ПК не требуются.
- Гость может тренироваться по публичной подборке без аккаунта; его оценки не записываются в аккаунт.
- Публичное приложение не имеет подключения к домашней сети и файловой системе ПК.
- Нынешняя коллекция, личные исправления, источники и история не теряются при переносе.
- Владелец управляет коллекцией; учащиеся читают разрешённую коллекцию и меняют только свой прогресс.
- Облако не означает абсолютную безопасность: доступ, обновления и восстановление проверяются отдельно.

## 2. Исходное состояние по коду

| Область | Сейчас | Что потребуется |
| --- | --- | --- |
| Интерфейс | React + TypeScript + Vite, готовые занятия и словарь | Сохранить экраны, заменить источник серверных данных |
| Публичная версия | GitHub Pages, `dist-static`, пакет на 600 записей | Сохранить гостевой режим, развернуть облачную сборку на Pages |
| API | `apps/web/src/api.ts` → Node HTTP API | Сохранить внешние типы, добавить облачный адаптер |
| База | `apps/server/src/database.ts`, SQLite | Миграции PostgreSQL, ограничения, индексы, RLS |
| Прогресс | Общие `review_state`, `review_log`, одна последняя отмена | Прогресс и отмена отдельно для каждого пользователя |
| Вход | HTTP Basic; отдельный `auth.ts` не подключён к API | Supabase Auth; собственные пароли и сессии SQLite не переносить |
| Коллекция | Base / Override, источники, теги, примеры, история | Сохранить семантику и разграничить публичные и закрытые данные |
| Редактор | Создание, исправление, удаление, восстановление, слияние | Авторизованные операции владельца и защита от конфликтов |
| Импорт | Локальные пакеты, preview, apply, rollback, внешние словари | Облачные операции и отдельная обработка тяжёлых задач |
| Эксплуатация | Windows autostart, Node, cloudflared, SQLite на ПК | Облачный выпуск, резервирование, мониторинг и отключение туннеля |

Текущие числа записей и ответов для переноса нужно измерить по согласованной копии
рабочей SQLite. Число 600 относится к публичному пакету, а не к гарантированному
размеру личной базы.

## 3. Целевая архитектура

```text
Браузер: React / Vite на Cloudflare Pages
  ├── публичная версионированная подборка → гостевая тренировка
  ├── Supabase Auth → регистрация, вход, восстановление доступа
  ├── Supabase Data API + RLS → разрешённое чтение
  ├── PostgreSQL RPC → атомарная оценка, отмена и операции коллекции
  └── Edge Functions → внешние словари и операции с серверными секретами
        └── Supabase PostgreSQL / при необходимости закрытый Storage

Отдельный контур: CI → проверка → миграции → сборка → публикация
Отдельный контур: резервная копия → защищённое хранилище → проверка восстановления
```

Домашний Node-сервер не переносится на Pages целиком. Его правила переносятся в
PostgreSQL, Edge Functions и инструменты обслуживания. Тяжёлые импорты не должны
выполняться целиком в одном браузерном или Edge-запросе.

### Рабочие допущения для первой облачной версии

- Закрытый пилот, затем регистрация для остальных; email + пароль с подтверждением адреса.
- Одна коллекция под управлением владельца. Личные коллекции каждого учащегося — следующий этап.
- Нынешние пользовательские исправления сохраняются в закрытом облачном каталоге.
  Они не становятся частью гостевого JSON автоматически.
- Нынешний общий прогресс предлагается назначить одному аккаунту владельца.
  Это решение подтверждается перед импортом; автоматически размножать его всем пользователям нельзя.
- История отмены из SQLite сохраняется в архивном экспорте; действующий токен отмены
  не переносится. После переключения отменяются только новые облачные ответы.
- Первоначально облачные занятия требуют сети. Гостевой режим не обещает офлайн-доступ,
  пока отдельно не реализованы service worker и кэш.
- Домен `.com` необязателен: пилот можно открыть на `pages.dev`, домен подключить позже.

M5 — пилот облачного обучения. M8 — полный переход с сохранением текущих функций.
До M8 SQLite остаётся источником нынешнего личного прогресса; пилот использует
тестовые данные и отдельную историю. Два независимых источника рабочего прогресса
одновременно не включаются.

## M4. Перенести учебную логику

- [x] Перенести выбор очереди, фильтры, направления, приоритет повторов и режим новых карточек.
- [x] Выполнять оценку одной транзакцией: проверить пользователя и карточку,
  сериализовать изменение его учебного состояния, вычислить интервал,
  записать событие и снимок отмены, вернуть новое состояние.
- [x] Вычислять расписание на доверенной стороне. Клиент не задаёт произвольный `due_at`.

- [ ] Сериализовать изменение состояния пользователя так, чтобы два первых ответа
  из разных вкладок не обходили блокировку ещё не существующей строки прогресса.
- [x] Сохранять последнюю отменяемую оценку отдельно для каждого пользователя;
  отмена не перезаписывает более новое состояние и не затрагивает другого пользователя.
- [ ] Перенести статистику, отдельно проверить даты, округление интервалов и часовые пояса.
- [x] Прогнать одинаковые сценарии SQLite и PostgreSQL на тестовых данных и сравнить результат.
- [ ] Проверить конкурентные ответы, повторный запрос, двойную отмену и потерю сети
  после успешной записи. Клиент показывает неопределённый результат до сверки с сервером.

**Готово:** обе реализации дают согласованные результаты; конкуренция и повторы
запросов не повреждают расписание, журнал и отмену.

- [ ] Определить отдельно резервирование Auth, схемы и данных, Storage и конфигурации;

- [ ] Проверить восстановление в изолированном окружении; задать исходные цели:
  потеря не более 24 часов данных при аварии, восстановление в течение рабочего дня.
- [ ] Измерить длительность переноса и согласовать окно остановки записи.

**Готово:** повторяемый перенос и проверенное восстановление; отчёт сравнения
объясняет каждое расхождение. Наличие файла резервной копии без восстановления не является приёмкой.

## M8. Переключить рабочее приложение

- [ ] Заморозить записи в старом сервере, завершить текущие занятия и снять финальную копию.
- [ ] Выполнить проверенный импорт в production; сохранить отчёт и идентификатор снимка.
- [ ] Проверить права, вход, расписание, оценку, отмену и редактор на финальных данных.
- [ ] Опубликовать клиент с production Supabase; подключить домен, если он выбран,
  и обновить Auth callback-адреса. Для запуска домен покупать необязательно.
- [ ] Обновить GitHub Pages: ссылка/перенаправление на новое приложение с учётом
  прежних `#/study`-маршрутов, без старого запроса адреса домашнего сервера.
- [ ] После приёмки остановить Node и cloudflared, удалить задачу автозапуска,
  отозвать домашние туннельные учётные данные, если они использовались.
- [ ] Убедиться, что старый сервер не продолжает принимать рабочие ответы;
  исходную SQLite-копию сохранить закрытой и неизменяемой.
- [ ] Обновить README, `docs/USAGE.md`, эксплуатационные инструкции и статус проекта.

**Готово:** полный учебный и административный сценарий проходит с выключенным ПК,
по постоянному адресу; домашний публичный вход отключён.

### План отката

До первых облачных записей: остановить новый выпуск, вернуть старый интерфейс
и прежний согласованный SQLite-снимок, затем разрешить запись только в старую систему.

После первых облачных записей: простое включение старого сервера потеряет новые ответы.
Нужно сначала остановить запись в облако, экспортировать новые изменения и либо
исправить облачную версию, либо выполнить заранее проверенный обратный перенос.
Если обратный перенос всех сущностей не реализован, после запуска основной путь —
исправление облака и восстановление из его копий, а не обещание мгновенного возврата к SQLite.
Откат клиентской сборки допускается только при совместимой схеме базы.

## 6. Бюджет и ограничения

Начинаем с бесплатных возможностей, но не обещаем нулевую стоимость при любом росте.
На дату плана Supabase Free указывает базу до 500 МБ, 50 000 активных пользователей
в месяц и приостановку после недели неактивности. Это отдельные лимиты: число
пользователей не гарантирует достаточную производительность и ёмкость журнала ответов.
Учитывать трафик резервных копий, отправку писем, Storage и вызовы функций.
Актуальные условия перепроверить на M1 и перед публичным выпуском.

Публичная регистрация зависит от настроенной доставки Auth-писем. На Free собственные
экспорты и проверка восстановления входят в обязательную эксплуатацию.
Домены и SMTP могут оплачиваться отдельно. До запуска задать допустимый месячный
бюджет и пороги перехода на платный тариф; приостановку Free не обходить искусственным трафиком.

## 7. Границы проекта

В текущую миграцию не входят: смена алгоритма повторения, новая система упражнений,
платежи, соцфункции, пользовательские приватные коллекции, совместная редактура,
офлайн-синхронизация ответов и переработка дизайна. Их можно планировать после M9.

Следующий внешний шаг — создание изолированного Supabase-пилота и Cloudflare Pages,
затем hosted-проверки M1–M5. Параллельно требуется реализация M6. UUID владельца,
SMTP, реальное восстановление в отдельный облачный проект и окно переключения
ещё не заданы. Покупка домена для пилота не нужна.
