# Контракт миграции SQLite → Supabase

## Права

| Действие | Гость | Учащийся A | Учащийся B | Владелец |
| --- | --- | --- | --- | --- |
| Публичная подборка | чтение | чтение | чтение | чтение |
| Закрытый общий каталог | нет | чтение | чтение | чтение/редактирование после M6 |
| Прогресс A | нет | чтение, оценка/отмена RPC | нет | нет |
| Прогресс B | нет | нет | чтение, оценка/отмена RPC | нет |
| Роли, токены отмены, снимки пакетов | нет | нет | нет | только отдельные проверяемые операции |
| Назначить владельца | нет | нет | нет | только оператор БД, не профиль/Data API |

Владелец изучает как обычный учащийся и не получает чтение чужой истории автоматически.
В нынешнем пилоте запись каталога закрыта для всех клиентских ролей. M6 ещё не реализован.
`private.collection_roles` недоступна через Data API. Пользовательские metadata Auth
не участвуют в определении роли.

## Поведение обучения

- Карточка определяется числовым ID и направлением; у записи ровно два направления.
  Импорт сохраняет ID; стабильный ключ — пара `sources.source_key / entries.source_key`.
  Одинаковое написание турецкого слова не объединяет записи.
- Очередь учитывает эффективные категорию, часть речи и теги, enabled/active,
  пользовательский статус и отсутствие удаления/слияния. Сначала просроченные,
  затем случайная новая карточка. Режимы `review` и `new` изолированы.
  Возврат к выбранной карточке допустим только если она ещё подходит очереди.
- Первые верные ответы: 1 день, затем 3 дня, затем `max(1, round(interval * ease))`.
  Ease увеличивается на 0.05 до 3. Неверный ответ: 5 минут, repetitions=0,
  ease уменьшается на 0.2 до 1.3, lapses увеличивается.
- Время назначает сервер; timestamps хранятся в UTC. День определяется IANA timezone
  профиля, при переносе `Europe/Moscow`, а не UTC-полуночью.
- `reviewedToday`, `correctToday`, `newUsedToday` относятся ко всему пользователю,
  включая оба направления и все фильтры. `due` и `newTotal` учитывают фильтры/направление.
  Это сохраняет нынешнюю семантику SQLite. Правильным считается rating `good`.
- `request_id` уникален на пользователя. Повтор с тем же содержимым возвращает
  сохранённый результат; другое содержимое с прежним ID отклоняется.
  Клиент также передаёт ожидаемый UUID аккаунта для защиты от смены сессии во время
  запроса. Этот UUID только проверяется на совпадение с `auth.uid()` и не назначает
  владельца записываемого прогресса.
- Advisory transaction lock по UUID пользователя сериализует оценки и отмену даже
  до создания первой строки review_state. Клиент не пишет review_state/review_log напрямую.
- Отменяется только последняя оценка данного пользователя, если состояние не изменилось.
  Снимок сравнивается целиком, ответ удаляется из журнала, прежнее состояние восстанавливается.
  Повторная отмена отклоняется. Receipt запроса сохраняется и после отмены:
  повтор исходного request ID не создаёт ответ заново.
- Пустые override-примеры и пустой пользовательский список тегов сохраняются.
  Обновление базовых значений не превращает их обратно в исходный текст/теги.

## Карта API и полнота

Методы `apps/web/src/api.ts` сохраняются в локальном режиме. Облачный адаптер
отклоняет неподключённые операции явно; домашнего fallback нет. Эта карта не является
согласованным исключением функций из полной версии: все M6-строки остаются обязательными.

| Метод клиента | Cloud | Этап |
| --- | --- | --- |
| fetchStats | cloud_stats | пилот, код готов |
| fetchEntries | cloud_entries | пилот, код готов |
| fetchEntryFilters | cloud_filters | пилот, код готов |
| fetchNextCard | cloud_next_card | пилот, код готов |
| submitReview | cloud_review | пилот, код готов |
| undoLastReview | cloud_undo | пилот, код готов |
| fetchEntryDetail | detail RPC | M6, не реализовано |
| createEntry / updateEntry / setEntryStatus | owner RPC, expected version | M6, не реализовано |
| deleteEntry / restoreEntry / fetchRemovedEntries | owner RPC | M6, не реализовано |
| mergeEntries | owner merge RPC с проверкой версий обеих записей | M6, не реализовано |
| fetchEntryRefreshSuggestion / applyEntryRefreshSuggestion | Edge + owner RPC | M6, не реализовано |
| searchOnlineWords / confirmOnlineWord | Edge + owner RPC | M6, не реализовано |
| checkLocalWord / verifyEntry / auditDictionary | read RPC / Edge | M6, не реализовано |
| fetchUpdateStatus / checkUpdatePackage | owner RPC / maintenance job | M6, не реализовано |
| applyUpdatePackage / rollbackUpdatePackage | transactional owner RPC | M6, не реализовано |
| prepareDictionaryImport / applyDictionaryImport | staging job + owner RPC | M6, не реализовано |

Служебные локальные `/api/health` и `/api/updates/preview` не являются методами
клиентского адаптера; в облаке им нужны отдельные эксплуатационные проверки/owner preview.
Старый HTTP Basic, `auth.ts` и Windows-файлы доступа в облако не переносятся.
