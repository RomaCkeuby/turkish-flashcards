# Автозапуск личного сервера на Windows

## Включение и управление

Из каталога проекта выполнить `pnpm personal:autostart`. Установка создаёт задачу
`TurkishFlashcards-Personal` для текущего пользователя и сразу запускает её.
При следующих входах в Windows она запускается автоматически, без окна терминала.
ПК должен быть включён, пользователь должен войти в Windows. Сон и выключение
прерывают доступ; настройки питания установщик не меняет.

Проверка выполняется каждые 30 секунд после завершения предыдущей проверки:
проверяется процесс туннеля и авторизованный `/api/stats` локального сервера.
При сбое перезапускается только неисправный компонент. Три неудачные проверки API
предшествуют перезапуску зависшего сервера. Cloudflared самостоятельно восстанавливает
сетевое соединение; отсутствие интернета не вызывает постоянную смену ссылки.
Остановка самого наблюдателя восстанавливается Планировщиком через минуту.

- `pnpm personal:start` — запустить вручную / возобновить после намеренной остановки.
- `pnpm personal:stop` — остановить сервер и туннель; наблюдатель уважает эту остановку
  даже после нового входа в Windows, пока не выполнен `personal:start`.
- `pnpm personal:autostart:remove` — удалить задачу и остановить наблюдатель;
  уже работающие сервер и туннель продолжат работать. Для их остановки выполнить `personal:stop`.
- `.personal/server-url.txt` — актуальная интернет-ссылка для телефона.
- `.personal/launch.json` — адрес и идентификаторы запущенных процессов.
- `.personal/watchdog.log` — ошибки автоматического восстановления.
- `.personal/access.json` — логин и пароль приложения; не публиковать.

Если установка задачи сообщает об отказе в доступе, запустить команду в PowerShell
с правами, достаточными для регистрации задачи. Учётная запись задачи должна быть
той же, что используется для проекта. Установка не сохраняет пароль Windows.
Путь проекта и Node фиксируется при установке: после их перемещения переустановить задачу.
Повторная установка обновляет определение задачи; для немедленного изменения уже
работающего наблюдателя сначала удалить автозапуск, затем установить снова.

Скрипты используют блокировку для исключения одновременных запусков. Перед остановкой
проверяются имя, PID и время создания процесса. Посторонний процесс на порту 3002
не останавливается. Сохранённые пароли и SQLite-база при восстановлении не заменяются.
Автоматическая пересборка приложения не выполняется: перед первым запуском нужен `pnpm build`.

## Постоянный адрес через Cloudflare

Сейчас без домена используется Quick Tunnel: случайная ссылка `trycloudflare.com`
меняется при создании нового туннеля. Перезапуск только Node сохраняет прежний туннель.
Источник: [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

Для постоянного публичного имени в этой схеме требуется собственный домен,
подключённый к Cloudflare. Покупка домена и изменение DNS выполняются владельцем.
Без этого шага автозапуск работает, но интернет-ссылка остаётся временной.

Когда домен появится:

1. Добавить его в Cloudflare и выполнить указания сервиса по смене NS у регистратора;
   дождаться активного состояния зоны.
2. В панели Cloudflare открыть раздел **Networking / Tunnels** (названия разделов
   могут меняться), создать туннель типа **Cloudflared**.
3. В команде подключения для Windows взять только токен и сохранить его локально
   в `.personal/tunnel-token.txt`, одной строкой. Команду `service install` выполнять
   не требуется: процессом уже управляют скрипты проекта. Токен не отправлять в чат
   и не добавлять в Git.
4. Добавить опубликованный маршрут / public hostname, например `cards.example.com`,
   с сервисом **HTTP**, адрес **127.0.0.1:3002**. Не включать обход авторизации приложения.
5. Создать `.personal/tunnel.json`:

   ```json
   { "url": "https://cards.example.com" }
   ```

6. Выполнить `pnpm personal:stop`, затем `pnpm personal:start`.
   Скрипт обнаружит настройку и запустит именованный туннель с `--token-file`.
   Проверить адрес на другом устройстве и сохранить закладку.
7. В окне подключения на GitHub Pages один раз ввести этот адрес. Браузер его запомнит.
   Открытие самой закладки сервера сразу приводит в личное приложение.

Это подготовленный путь настройки; без домена и токена именованный туннель
не активирован и его внешняя доступность не проверена. Для возврата к Quick Tunnel
убрать `.personal/tunnel.json` и выполнить остановку/запуск.

Документация: [создание туннеля](https://developers.cloudflare.com/tunnel/get-started/),
[параметры запуска](https://developers.cloudflare.com/tunnel/reference/run-parameters/).
