# Как подключаться и где хранятся данные

Миграция в облако начата 3 ноября 2026, но рабочий сайт пока использует прежнюю
архитектуру ниже. Облачный адрес ещё не опубликован, SQLite остаётся источником
личного прогресса. Код пилота, снимок и результаты локального восстановления:
[CLOUD-MIGRATION.md](CLOUD-MIGRATION.md).

Актуализировано 2 ноября 2026 года по текущему коду и рабочей SQLite-базе. Описано реализованное поведение, а не будущие возможности roadmap.

## 1. Занятия без включённого ПК

Постоянный адрес: https://romackeuby.github.io/turkish-flashcards/

Прямая ссылка на тренировку TR → RU:
https://romackeuby.github.io/turkish-flashcards/#/study?direction=tr-ru

1. Открыть адрес на телефоне или компьютере с интернетом.
2. Оставить свободный режим, выбрать направление и при необходимости фильтры.
3. Открывать перевод и оценивать ответы. Счётчики относятся только к текущему проходу; персональное расписание не сохраняется.

Здесь интерфейс и публичная подборка размещены на GitHub Pages. Домашний ПК, локальный сервер и Cloudflare Tunnel не участвуют. В подборке 600 записей и два направления (1200 учебных карточек).

`#/` — часть маршрута статической версии; удалять её из прямой ссылки не нужно.

Интернет для загрузки сайта нужен. Полноценная работа после нового открытия браузера без интернета пока не реализована. Подборка и результаты прохода находятся в памяти страницы; уход со страницы занятия/перезагрузка сбрасывают проход. Сохранения прогресса в IndexedDB пока нет.

Кнопка серверного режима на GitHub Pages пока не подключает ваш ПК: настройка удалённого API и вход в аккаунт ещё не реализованы. Для сохранения текущего общего прогресса использовать адрес ПК из следующего раздела.

## 2. Личная коллекция и сохранение общего прогресса на ПК

На самом ПК:

- обычная разработка: http://127.0.0.1:5173/ после `pnpm dev`;
- запущенная личная production-версия: http://127.0.0.1:3002/ после `pnpm personal:start`.

На телефоне использовать HTTPS-ссылку, которую выдаёт `pnpm personal:start`. Текущий сохранённый адрес на дату проверки:

https://stockings-stat-identification-situation.trycloudflare.com/

Тренировка:
https://stockings-stat-identification-situation.trycloudflare.com/study?direction=tr-ru

Это адрес домашнего ПК через туннель. ПК должен быть включён, сервер и туннель запущены, интернет доступен. После повторного создания Quick Tunnel адрес может измениться. Актуальный сохранённый адрес можно вывести на ПК без показа пароля:

```powershell
(Get-Content -LiteralPath .personal/launch.json -Raw | ConvertFrom-Json).url
```

При входе браузер запрашивает общий логин и пароль доступа к серверу. Они сохраняются локально в `.personal/access.json`; не публиковать и не пересылать этот файл. Общий пароль защищает весь сайт и API; это ещё не отдельный аккаунт учащегося.

В серверном режиме («На ПК» / «Сервер на ПК») доступны рабочая коллекция, правки, история, расписание повторений и сохранение ответов в SQLite. В свободном режиме на этом же адресе используется опубликованная подборка из файлов локальной сборки; сервер всё равно нужен для загрузки самого сайта. Такая ссылка не заменяет GitHub Pages при выключенном ПК.

В серверном обработчике исправлена выдача JSON-подборки: раньше HTML и JS загружались, а `/decks/manifest.json` возвращал 404, из-за чего свободный режим показывал ошибку. Исправление собрано и применено перезапуском только серверного процесса 2 ноября 2026 года. Проверено: локально доступны все 600 записей и API статистики; через прежний туннель manifest сообщает 600 записей, `/healthz` отвечает 200. Для получения исправления обновить страницу в браузере. Сам туннель не перезапускался.

## 3. Где лежат интерфейс и данные

Все локальные пути ниже относительны к корню этого проекта.

| Что | На ПК | На GitHub Pages |
| --- | --- | --- |
| Исходники интерфейса | `apps/web/src` | Исходники доступны в репозитории; посетитель получает собранный сайт |
| Собранный серверный интерфейс | `apps/web/dist` | Не используется |
| Собранный независимый интерфейс | `apps/web/dist-static` | GitHub Actions публикует содержимое этого каталога |
| Публичные карточки | `apps/web/public/decks/manifest.json` и `cards.<hash>.json`; копируются в сборку | `/turkish-flashcards/decks/manifest.json` и файл из поля `file` |
| Источник публичной подборки | `apps/server/update-packages/current/manifest.json` и `cards.jsonl.gz` | Используется только при сборке; браузер читает публичный JSON |
| Рабочие карточки, личные исправления, ответы и расписание | `apps/server/storage/turkish-flashcards.db` | Не размещены и не доступны сайту Pages |
| Общий пароль доступа к ПК | `.personal/access.json` | Не размещён |
| Профили пользователей и их отдельный прогресс | Пока не подключены к рабочему приложению | Отсутствуют |

Нельзя считать `dist` или `dist-static` исходным хранилищем карточек: это результаты сборки. Рабочая SQLite-база и публичная подборка — два отдельных набора. Изменения в редакторе ПК не переносятся в публичный JSON автоматически; ответы на Pages не попадают в SQLite.

## 4. Текущий статус аккаунтов

В рабочей базе проверен список таблиц: `users`, `auth_sessions` и `auth_invitations` отсутствуют. Прогресс хранится в общих `review_state`, `review_log` и `review_undo`.

Подготовлены и протестированы модуль `apps/server/src/auth.ts` и будущий контракт `docs/hybrid-auth-api.md`. Модуль не подключён к HTTP API и рабочей базе. Создать профиль, войти в него и получить отдельный прогресс в текущем приложении пока нельзя. Вход в GitHub также не создаёт аккаунт в приложении.

Следующий этап: персонализировать SQLite-прогресс, подключить регистрацию/сессии к серверу, затем добавить на постоянном сайте настройку адреса API и вход. До этого два сайта не синхронизируют личные данные.

## 5. Как обновляются версии

- `pnpm build` собирает локальные сервер и интерфейс. Чтобы процесс Node загрузил исправления серверного кода, его нужно перезапустить. Обновление веб-страницы не перезапускает Node.
- `pnpm build:static` воспроизводимо создаёт публичный пакет и статическую сборку. Для текущего Pages задаётся `VITE_BASE_PATH=/turkish-flashcards/`.
- Push в `codex/hybrid-offline-accounts` или `main` запускает Pages workflow, если эта ветка содержит `.github/workflows/pages.yml`. Сайт обновится после успешного deploy, а не после одного локального сохранения файла.
- Незакоммиченные изменения интерфейса на ПК не появляются на GitHub Pages автоматически. Поэтому внешний вид локальной/туннельной версии может отличаться от опубликованной.
- Базу SQLite, пароли, `.personal` и `.tools` в публикацию не включать. Для копии действующей SQLite учитывать WAL; простое копирование одного файла открытой базы может не сохранить последние изменения.

## 6. Какой адрес выбрать

- Просто тренировать карточки независимо от ПК → постоянный адрес GitHub Pages.
- Сохранять нынешний общий прогресс и редактировать рабочую коллекцию → запущенный сервер на ПК или его актуальная ссылка туннеля, серверный режим.
- Отдельный профиль и общий прогресс между устройствами через аккаунт → следующий этап разработки, сейчас недоступен.
