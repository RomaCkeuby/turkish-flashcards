# Задания агентам: гибридное приложение

Это задания для будущих запусков агентов, а не отчёт о выполнении. Общий план: [ROADMAP-HYBRID.md](../ROADMAP-HYBRID.md).

## Файлы заданий

1. [01-interface.md](01-interface.md) — интерфейс, гостевой режим, подключение аккаунта, статическая сборка и кэш.
2. [02-cards.md](02-cards.md) — публичный пакет, локальная колода, разделение прогресса в SQLite.
3. [03-remote-access.md](03-remote-access.md) — серверная авторизация, права, CORS и доступ через туннель.

Каждый агент сначала читает этот файл, своё задание и roadmap. Исполняет один согласованный подэтап, затем проверяет результат и передаёт отчёт. Реальные секреты, рабочая база и действующий туннель не меняются ради тестов. Проверки выполняются на отдельной базе и тестовых настройках.

## Общие решения первой версии

- Постоянный сайт с публичной подборкой работает без ПК. Аккаунты и их прогресс доступны только при подключении к ПК.
- Общая коллекция, отдельный прогресс пользователей. Изменение коллекции доступно владельцу; учащемуся доступны чтение и собственные ответы.
- Создание аккаунтов — по одноразовому приглашению владельца. Существующий прогресс мигрирует первому владельцу один раз.
- Гостевые ответы не отправляются серверу и не объединяются с аккаунтом.
- Локальный режим на ПК должен сохраняться; остановка сервера не блокирует гостевые экраны постоянного сайта.
- Новые зависимости, изменения общих scripts и общей конфигурации оформляются предложением координатору; lockfile обновляет координатор после согласования. Это граница владения файлами, а не требование отдельного разрешения пользователя.

## Общие контракты перед реализацией

Координатор фиксирует следующий контракт в коде/фикстурах до интеграции. Приведённые имена — целевой проект, не существующий API.

### Публичная подборка

`PublicCardEntry`: `key`, `turkish`, `russian`, `partOfSpeech`, `category`, `tags`, `exampleTurkish`, `exampleRussian`, `sources`.

`sources`: массив объектов с `name`, `url`, `license` и назначением источника (`entry`, `example`, `exampleTranslation`). Сохранять всю имеющуюся атрибуцию.

`PublicDeckManifest`: `schemaVersion`, `version`, `recordCount`, `file`, `sha256`.

`key` стабилен между сборками; это не числовой ID строки SQLite. В первой версии брать идентичность из источникового пакета и явно определить поведение при изменении ключа. Нельзя обещать устойчивость ключа из одного изменяемого написания слова.

### Браузерная колода

Чистый модуль `apps/web/src/guestDeck.ts`, владелец — агент карточек. Вход: подборка, направление, фильтры, внедряемый источник случайности. Выход: последовательность карточек без повторов внутри прохода. Интерфейс модуля и тестовая фикстура согласуются до одновременной работы.

### Подключение и сессия

- Клиент различает транспортную недоступность, 401, 403 и несовместимую версию API.
- Запрос проверки возможностей возвращает версию API и доступные функции без персональных данных.
- Сессия: непрозрачный отзываемый bearer-токен, в первой версии хранится только в памяти клиента; сервер хранит хеш и срок действия. После перезагрузки нужен вход. Постоянное хранение — отдельное решение.
- Точные URL, тела запросов и формат ошибок согласует агент удалённого доступа с интерфейсным до реализации; контракт не должен зависеть от third-party cookies.
- Оценка содержит `operationId`; её повтор с тем же пользователем и содержимым возвращает прежний результат. Повтор идентификатора с другим содержимым отклоняется. Оценка и запись результата операции фиксируются одной транзакцией.
- Вызовы SQLite получают доверенный контекст пользователя от сервера; клиентский `userId` не определяет доступ.

## Владение файлами

| Область | Владелец |
| --- | --- |
| `apps/web/src`, кроме `guestDeck.ts` и его тестов | Интерфейс |
| `apps/web/vite.config.ts`, `apps/web/index.html`, новые статические ресурсы/PWA | Интерфейс |
| `apps/web/src/guestDeck.ts`, `apps/web/test/guestDeck.test.ts` | Карточки |
| `apps/server/src/database.ts`, тесты БД, новые модули экспорта и прогресса | Карточки |
| `apps/server/src/index.ts`, `hosting.ts`, тесты hosting, новые модули auth/access | Удалённый доступ |
| `scripts/Start-Personal.ps1`, `Stop-Personal.ps1`, новые скрипты подключения | Удалённый доступ |
| Корневые package scripts, package manifests/lockfile, CI, общие типы, `.env.example`, итоговый README | Координатор, по предложениям агентов |

Агент удалённого доступа реализует auth-хранилище отдельным модулем и согласует порядок миграций с агентом карточек; не редактирует `database.ts` одновременно с ним. Агент карточек не меняет `index.ts`: передаёт новые сигнатуры и примеры вызова владельцу API. Существующие таблицы и запросы прогресса необходимо проверить полностью, а не ограничиться добавлением `user_id`.

## Порядок запуска

1. Координатор утверждает форматы и ограничения; проверяет доступные команды и исходные регрессии.
2. Параллельно: интерфейс I1 на фикстуре; карточки C1; удалённый доступ R1 как проектирование контракта и отдельный модуль авторизации.
3. Интеграция гостевого сайта; приёмка без сервера.
4. Карточки C2 и удалённый доступ R2 работают по согласованному контракту и отдельным файлам; интерфейс I2 использует фикстуры ответов.
5. Интеграция реального API и входа; I3 и R3; проверки на телефоне.
6. Координатор принимает итог, объединяет конфигурацию и готовит выпуск.

При запуске из этого чата три агента занимают все доступные исполнительские слоты; основной агент остаётся координатором. Выполнение зависимых подэтапов не начинается до приёмки их входных контрактов.

## Формат отчёта агента

- Законченный подэтап и фактическое поведение.
- Изменённые файлы, команды проверок и результаты.
- Изменения контрактов и инструкции интеграции.
- Ограничения и оставшиеся задачи; никаких неподтверждённых заявлений о работе на телефоне или опубликованном сайте.
