# Интерфейс: отчёт первой волны I1

Дата: 2 ноября 2026. I2/I3 не выполнялись.

## Поведение

- Обычная серверная сборка и dev по умолчанию открывают существующий серверный режим. Статическая сборка открывает гостя без обращений к API.
- Над страницей есть явный переключатель «Свободная тренировка» / «Сервер на ПК». Переключение размонтирует предыдущие экраны и возвращает на главную: идентификаторы гостевых карточек не передаются SQLite API.
- Гостевые маршруты: `/` — описание и выбор направления; `/study` — колода; `/dictionary` — поиск, три фильтра и страницы по 30 записей; `/card/:entryId` — чтение по закодированному стабильному ключу; `/settings` — версия подборки и описание доступности функций.
- Колода формируется один раз для прохода, а не на каждую оценку. Смена направления/фильтров и «Новый проход» начинают другую тренировку. Есть переворот, оценки, отмена последней гостевой оценки, счётчики текущего прохода, горячие клавиши.
- Гостевые ответы не вызывают API и не записываются в аккаунт. Редактор, импорт и персональное расписание доступны только на существующих серверных экранах.
- Источники и лицензии отображаются в деталях и на стороне ответа. Некорректный ключ даёт понятное состояние отсутствующей карточки.
- Подборка загружается один раз в память, с manifest по `${BASE_URL}decks/manifest.json`. Проверяются схема, SHA-256 фактических байтов, количество, ключи и формат источников. Ошибка допускает повторную загрузку.

## Сборка и маршруты

- `vite build --mode static` определяет `VITE_STATIC_SITE=1`; также можно задать эту переменную явно.
- `VITE_BASE_PATH` задаёт путь публикации, например `/repository/`. Он применяется к ресурсам Vite и manifest/JSON подборки.
- Статический режим использует HashRouter: ссылка на карточку имеет вид `/repository/#/card/<key>`, поэтому обновление не требует серверного fallback.
- Обычный режим сохраняет BrowserRouter и существующие URL.
- Статическая сборка пишет в `apps/web/dist-static`, обычная — в `apps/web/dist`: сборки не заменяют артефакты друг друга. Для preview статической сборки указывать `--outDir dist-static`.
- Корневые scripts `decks:build`, `build:static` и web scripts добавляет координатор; агент интерфейса package manifests не менял.

## Проверки

- `pnpm --filter @turkish-flashcards/web typecheck` — успешно.
- `pnpm --filter @turkish-flashcards/web test` — 14 тестов успешно, включая 5 новых тестов mode/loader/валидации и тесты колоды от агента карточек.
- Первое `pnpm build:static` выполнило генерацию 600 записей и tsc, затем esbuild остановился на ограничении чтения родительского каталога песочницей. Координатор выполняет повторную сборку с нужным доступом и проверку браузером, включая путь `/hybrid-test/`.
- Проверка реального телефона, публикация на GitHub Pages и проверка работы без интернета не выполнялись этим агентом.

## Исправление после browser smoke

Первый browser smoke координатора выявил несовместимость полной подборки с проверкой URL: источник `local://curated-basic-v1` обозначает локальную исходную подборку. Парсер теперь допускает именно это значение как атрибуцию, а интерфейс отображает его обычным текстом. Ссылки создаются только для HTTP(S); неизвестные `local://`, `file://` и опасные схемы по-прежнему отклоняются.

Добавлены проверки полного сгенерированного пакета через настоящий браузерный загрузчик (manifest, схема, SHA, количество и все записи) и локальной атрибуции. Это закрывает пробел первоначального тестирования только на малой фикстуре.

После исправления повторно прошли web typecheck и все 16 web-тестов. Повторную сборку и browser smoke выполняет координатор.

## Ограничения первой волны

- Удалённый URL сервера, регистрация и bearer-сессии относятся к I2. Серверный режим пока использует существующий API.
- Service worker и сохранение сайта без интернета относятся к I3. Интерфейс не заявляет, что кэш уже готов.
- Состояние гостевого прохода хранится внутри экрана и сбрасывается после ухода с него/обновления страницы; серверное сохранение учебной сессии не менялось.
