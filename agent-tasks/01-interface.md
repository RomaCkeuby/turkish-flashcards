# Агент 1: интерфейс и независимый сайт

Сначала прочитать `agent-tasks/README.md` и `ROADMAP-HYBRID.md`. Выполнять подэтапами I1 → I2 → I3. Не запускать дополнительные агенты автоматически.

## Цель

Существующий интерфейс работает как самостоятельный сайт: свободная тренировка доступна без ПК, а подключение к серверу открывает аккаунт и персональное расписание.

## Границы

Владение — по таблице README. Не менять сервер, SQL и модуль `guestDeck.ts`. Не создавать собственную конкурирующую реализацию алгоритма колоды. Сохранить текущие стили, мобильную адаптацию, горячие клавиши и существующий локальный серверный режим.

Основные исходные файлы: `apps/web/src/api.ts`, `App.tsx`, `main.tsx`, `studySession.ts`, страницы `DashboardPage`, `StudyPage`, `DictionaryPage`, `CardDetailPage`, `SettingsPage`.

## I1. Гостевой интерфейс

Вход: публичные типы и фикстура от координатора; затем пакет и модуль колоды от агента карточек.

- Отделить серверный источник от публичной подборки без переписывания всех экранов.
- При первом открытии показывать доступную гостевую функциональность; не ждать неработающий сервер.
- Добавить явный режим свободной тренировки, направления, фильтры, переворот, проход по перемешанной колоде и состояние пустой выборки.
- Счётчик гостевых ответов обозначать как статистику тренировки, а не прогресс аккаунта.
- Главная, словарь, детали карточки и настройки не должны падать от отсутствия API.
- Для редактирования, импорта и других серверных функций показывать доступность согласно режиму и роли.
- Сделать статическую сборку совместимой с базовым путём репозитория и обновлением вложенного маршрута. Выбранный способ маршрутизации задокументировать.

Приёмка: production-сборка обслуживается статическим сервером; API полностью недоступен; все гостевые экраны и колода работают, включая прямые ссылки.

## I2. Сервер и аккаунты

Вход: контракт API от агента удалённого доступа. До готовности API использовать изолированные фикстуры.

- Настройки адреса HTTPS API с проверкой формата и явным показом выбранного сервера перед вводом пароля.
- Состояния подключения, доступности сервера, несовместимости API, входа, выхода и истёкшей сессии.
- Регистрация по приглашению и вход, имя пользователя и роль.
- Сессионный токен только в памяти в первой версии; не писать пароли/токены в URL, журналы и публичный кэш.
- Отмена старых запросов при смене сервера и пользователя; личные ответы не должны появляться после выхода или у другого пользователя.
- Персональные очередь, статистика и отмена используют сервер; нельзя выдавать гостевые данные за персональные.

Приёмка: два пользователя на одном устройстве поочерёдно видят только свой прогресс; учащийся не получает элементы управления владельца; сервер остаётся окончательной проверкой прав.

## I3. Сбои и сохранение сайта

- Добавить operationId при отправке оценки; повтор использует тот же ID и тот же запрос.
- Различать подтверждённую оценку, ошибку и неизвестный результат. При неизвестном результате не сообщать «не сохранено» без проверки.
- При обрыве сохранить видимую карточку, предложить свободную тренировку; после восстановления не переключать занятие автоматически посреди ответа.
- Реализовать service worker, установочный manifest и версионирование публичного кэша. Не сохранять авторизованные API-ответы.
- Полная проверка нового пакета перед заменой старого; повреждённое обновление не уничтожает рабочую подборку.
- Показать готовность к занятиям без интернета. Проверить отсутствие кэша и несовместимую схему.

Приёмка: после предварительной загрузки сайт заново открывается без сети; отключение туннеля не ломает свободную тренировку; обновление не смешивает несовместимые ресурсы.

## Проверки и передача

Запустить доступные проверки web, typecheck и production build через координатора, если нужны изменения общих scripts. Добавлять содержательные тесты переходов режима, отмены запросов и обработки неизвестной оценки; не тестировать копию реализации.

Передать снимки/результаты проверки узкого экрана, состояние без API, договорённости о маршрутах и перечень файлов/настроек публикации. Проверку реального телефона указывать только после фактического прогона.
