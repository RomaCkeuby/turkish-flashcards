# Агент 3: аккаунты и удалённый доступ к ПК

Сначала прочитать `agent-tasks/README.md` и `ROADMAP-HYBRID.md`. Выполнять R1 → R2 → R3. Не запускать дополнительные агенты автоматически.

## Цель

Подключить независимый HTTPS-сайт к домашнему API через туннель, предоставить аккаунты и права, сохранить существующий локальный запуск.

## Границы

Основные файлы: `apps/server/src/hosting.ts`, `index.ts`, тесты hosting, `scripts/Start-Personal.ps1`, `Stop-Personal.ps1`. Auth-хранилище и миграции оформлять отдельным модулем; работу с `database.ts` согласовывать с агентом карточек. Не менять экраны и алгоритм повторений.

## R1. Контракт и авторизация

- Изучить текущие Basic Auth, обработку Origin, OPTIONS и ограничения тела запросов; составить матрицу доступа к каждому существующему маршруту.
- Зафиксировать API проверки версии/возможностей, регистрации по приглашению, входа, выхода и текущего пользователя. Передать примеры агенту интерфейса.
- Реализовать users, роли, приглашения и сессии отдельным модулем с согласованным порядком миграций.
- Пароли: солёное вычислительно затратное хеширование; приглашения и сессии: криптографически случайные значения, хеши на сервере, срок действия и отзыв.
- Ограничить перебор входа; не раскрывать пароли и токены в ошибках/журналах.
- Описать безопасное начальное создание владельца без опубликованного стандартного пароля. Не менять существующий пароль/аккаунт на рабочем ПК автоматически.

Приёмка: тесты истечения/отзыва сессии, одноразового приглашения, неверного пароля и запрета создания владельца обычным пользователем. Примеры контрактов пригодны для параллельной реализации интерфейса.

## R2. HTTP API и междоменные запросы

Вход: сигнатуры персонального прогресса от агента карточек.

- Для пользовательских операций получать контекст только из проверенной сессии; запретить обход через старые маршруты.
- Учащийся читает каталог и пишет свой прогресс; владелец управляет общей коллекцией и приглашениями.
- Настроить точный allowlist HTTPS origins сайта и необходимые preflight. Origin не заменяет авторизацию.
- Переработать взаимодействие Basic Auth и аккаунтов: браузер должен выполнять разрешённый preflight и вход. Не отключать всю защиту приложения ради CORS.
- Разделить общедоступный liveness/метаданные совместимости и приватные API; персональные ответы — no-store.
- Вернуть различимые ошибки недоступной авторизации, отсутствия прав, несовместимости и конфликтного operationId.
- Не использовать зависимость от сторонних cookies; соблюдать согласованный bearer-контракт.
- Ограничить доверие к proxy headers; не полагаться на произвольный клиентский заголовок для определения защищённого адреса или личности.

Приёмка: production-политика разрешает доверенный сайт, отклоняет чужой origin в браузере; без сессии нельзя читать прогресс или менять данные; сессия учащегося не меняет коллекцию. Проверить реальные HTTP-запросы, а не только снимки заголовков.

## R3. Туннель и эксплуатация

- Сохранить первый вариант с ручным вводом адреса временного туннеля. Не размещать адрес сервера и секреты в публичной подборке.
- Подготовить отдельную инструкцию постоянного адреса: необходимые аккаунт/домен/конфигурация указывать честно, не обещать их наличие.
- Привести скрипты запуска к новой конфигурации, сохранив привязку сервера к loopback и существующее управление процессами.
- Не останавливать действующий туннель и не менять настройки аккаунта провайдера для проверки кода. Тестовый запуск изолировать; реальное переключение выполнять отдельным шагом выпуска.
- Документировать allowlist origins, локальный запуск, приглашение пользователей, смену адреса, отзыв сессий и диагностику 401/403/сетевых ошибок.
- При использовании новой библиотеки, API или конфигурации провайдера сверить актуальную официальную документацию доступными инструментами.

Приёмка: независимый сайт на телефоне входит в тестовый аккаунт через туннель и сохраняет оценку; остановленный сервер не мешает гостю; после смены адреса вход выполняется явно заново. Если реальное окружение недоступно, указать этот непроверенный пункт в отчёте.

## Проверки и передача

Передать матрицу маршрутов/прав, контракт HTTP с примерами, список переменных окружения без значений секретов, миграционный порядок, инструкции запуска и результаты тестов. Корневую конфигурацию, `.env.example` и итоговый README передать координатору как конкретные изменения для интеграции.
