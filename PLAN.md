# PLAN.md

Пошаговый план разработки локального приложения Turkish Flashcards посредством Codex.

## Правила работы

1. Выполнять один этап или подэтап за один запрос Codex.
2. Не переходить дальше, пока текущий этап не запускается и не проверен.
3. После каждого изменения запускать проверки.
4. Не добавлять функции, отсутствующие в текущем этапе.
5. Не проводить крупный рефакторинг одновременно с добавлением функции.
6. Сначала добиться правильной работы на локальных mock-данных, затем подключать импорт больших наборов.

## Этап 1. Каркас monorepo

### 1.1 Создать pnpm workspace

Создать:

```text
apps/web
apps/server
packages/shared
```

Настроить корневой `package.json`, `pnpm-workspace.yaml`, общие scripts и TypeScript.

### 1.2 Создать React-приложение

В `apps/web` создать Vite + React + TypeScript приложение с React Router.

Маршруты:

```text
/
/study
/dictionary
/settings
```

На этом этапе не создавать сервер, базу данных и бизнес-логику.

## Этап 2. Локальная база

### 2.1 SQLite и начальная коллекция

Реализовано:

- локальный API в `apps/server`;
- SQLite-база, создаваемая при первом запуске;
- 250 базовых турецких слов и выражений;
- 500 карточек в направлениях TR → RU и RU → TR;
- поиск по словарю и выдача случайной учебной карточки;
- отдельные таблицы прогресса для будущего алгоритма повторений.

### 2.2 Уровень изучения

Реализовано:

- оценки `Верно` и `Неверно` после открытия перевода;
- сохранение истории каждого ответа;
- повтор неверного ответа через 5 минут;
- интервалы верных ответов 1 день, 3 дня и дальнейший рост по коэффициенту;
- приоритет просроченных карточек перед новыми.

### 2.3 Учебная очередь и статистика

Реализовано:

- дневной лимит новых карточек: 20 карточек в день;
- отдельный приоритет просроченных повторений перед новыми карточками;
- дата первого изучения карточки для подсчёта дневного лимита;
- статистика очереди: к повторению, новые сегодня, изучено сегодня, верные ответы и точность;
- состояние «На сегодня всё», когда повторений нет и дневной лимит новых карточек исчерпан;
- отображение учебной статистики на главной странице и на экране занятия.
- примеры употребления на стороне ответа из открытых Turkish-Russian пар Tatoeba с атрибуцией источника.

## Этап 3. Обновление коллекции из интернета

Реализовано:

- импорт Turkish Wiktionary данных из Kaikki/trwiktionary extract;
- сборка компактного пакета `cards.jsonl.gz`;
- `manifest.json` с версией, количеством записей и SHA-256 пакета;
- API preview: добавлено, изменено, отключено;
- транзакционное применение пакета к SQLite с сохранением прогресса карточек;
- снимок словаря перед обновлением и откат последнего обновления;
- блок обновлений в настройках приложения;
- автоматическая еженедельная проверка статуса пакета при запуске API.

Следующий подэтап: расширить пакет за пределы 250 базовых слов и добавить удалённый manifest для настоящей фоновой проверки новой версии.

## Этап 4. Просмотр и редактирование карточек

Реализовано:

- архитектура Base / Override: обновления меняют только base-слой, пользовательские override-данные не перезаписываются;
- таблицы для нескольких переводов, нескольких примеров, тегов, статусов и истории изменений;
- страница объекта карточки `/card/:entryId` с полной информацией, источниками и учебным прогрессом;
- редактирование турецкого слова, русского перевода, части речи, категории, тегов и примера;
- статусы `ACTIVE`, `DISABLED`, `ARCHIVED` без удаления карточек;
- минимальная история пользовательских изменений;
- словарь ведёт на страницу просмотра карточки;
- проверка, что apply/rollback интернет-обновления не удаляет пользовательский override и прогресс повторений.

## Этап 5. Расширение коллекции и персональное пополнение

Реализовано:

- update-пакет расширен до 600 записей;
- добавлено 350 новых слов из Kaikki/trwiktionary только при наличии русского перевода и Tatoeba-примера;
- подробный preview показывает конкретные изменённые и новые слова;
- словарь запрашивает до 1000 записей, чтобы работать после расширения;
- форма ручного добавления слова на странице словаря;
- пользовательская запись создаёт source `Пользователь`, обе учебные карточки, перевод, пример, теги и историю.
